# 架构说明

x-reader 0.1.4 是 Chrome 116+ 的 Manifest V3 扩展，使用原生 JavaScript ES Modules。根目录直接加载；没有编译步骤、后台工作线程、远程接口、AI、账号配置或运行时依赖。

## 模块与数据流

| 文件 | 职责 |
| --- | --- |
| `manifest.json` | `storage` 权限、X/Twitter 内容脚本范围、弹窗和可访问模块资源声明。 |
| `src/content/entry.js` | 经典内容脚本入口，通过 `chrome.runtime.getURL` 动态导入模块，防止重复启动，处理弹窗消息。 |
| `src/content/outline.js` | 阅读路由判断、正文定位、语义和启发式标题提取、跳转目标矩形。 |
| `src/content/reader.js` | 页面生命周期、扫描调度、目录状态、滚动定位、高亮、布局与主题。 |
| `src/content/panel.js` | Shadow DOM 内的紧凑目录、图标按钮与当前章节渲染。 |
| `src/content/drag.js` | 顶部指针拖动、Alt + 方向键移动、视口边界限制与拖动监听清理。 |
| `src/content/styles.js` | 隔离面板样式、主题变量、窄屏布局和减少动画适配。 |
| `src/shared/settings.js` | 设置默认值、归一化、串行保存与存储变更订阅。 |
| `src/popup/` | 当前页面状态、目录控制与阅读偏好。 |

内容脚本加载设置后定位当前正文，将提取结果交给面板；点击章节使用其 DOM 元素或文本 `Range` 定位。弹窗向当前标签页发送 `x-reader:status`、`x-reader:toggle`、`x-reader:refresh` 消息，直接与内容脚本通信，不经过后台。设置通过 `chrome.storage.local` 保存，并由变更监听同步到页面。

## 正文定位与标题识别

路由限定为 X/Twitter 的 `/<用户>/status/<数字>` 与 `/<用户>/article/<数字>`、`/i/article/<数字>`、`/i/articles/<数字>`，不在首页信息流拼接目录。正文优先取主列中的 Articles 富文本容器，或通过时间链接对应当前帖子 ID 的主帖 `tweetText`；DOM 选择器依赖 X 的实际结构。

按正文顺序遍历：

1. 识别 `h1`–`h6` 或 `role="heading"`，使用标签级别或 `aria-level`；定位到的文章主标题用于工具栏弹窗状态。
2. 将文本按块、换行和 `br` 分行。启发式候选长度为 2–80 字符，排除句末标点、含链接的行等。
3. 根据设置接纳整行加粗的短文本，或符合中英文编号前缀的短行；这两类使用二级标题层级。
4. 过滤引用、代码、列表项、隐藏节点、引用帖和扩展自身节点等，避免把非正文内容加入目录。

存在原生 H1–H6 章节时，最终目录只采用语义标题，避免混入表格表头、导读卡片和正文中的编号引用。

这些规则不会理解文章语义，不能保证正确区分所有小标题与正文。仅处理已加载到 DOM 的内容；不获取完整文章、不调用私有接口、不绕过访问限制。目录目标保持为元素或 `Range` 引用，不为正文写入永久锚点；页面文本以 `textContent` 渲染。

## 页面生命周期与交互

- `MutationObserver` 观察正文相关变化，以约 160 ms 的窗口合并扫描；扩展自身节点变化被忽略。
- 每约 700 ms 检查路径，并监听 `popstate`，覆盖 X 的 SPA 切换。路径改变时移除旧目录并重置手动展开状态。
- 被动滚动监听通过 `requestAnimationFrame` 更新当前章节；跳转保留约 96 px 顶部偏移。章节跳转在系统要求减少动画时取消平滑滚动。
- 点击或上下键先更新选中态再调用滚动；平滑滚动期间锁定目标，通过元素或文本 Range 起点在重新扫描后匹配目标。到达目标的 `scrollend`、3 秒超时、用户手动滚动或点击正文时解除锁定；关闭、切换文章和销毁均清理状态与定时器。
- 上下方向键只在目录展开时导航，边界不循环；忽略输入框、可编辑节点、输入控件、组合快捷键、已被处理的按键事件及输入法组合过程。
- 关闭功能时断开 DOM/主题观察、清理定时器与页面事件、移除 UI；保留设置订阅供重新启用。销毁时一并取消订阅。
- 目录无标题时不自动显示；用户手动展开可查看空状态提示；正文变化时自动更新。

## 布局与主题

面板是独立固定浮层，以 Shadow DOM 隔离样式，不改写 X 的正文布局。优先定位可见的 `sidebarColumn`，从趋势条目或趋势标题找到卡片，采用卡片的横向位置和宽度，并从该区域顶部向窗口底部延伸，留下 16 px 边距；没有趋势卡片时优先放在相关用户卡片下方。只接纳正文右侧、宽度至少 280 px 且位于视口内的侧栏。目录展开时覆盖该区域，收起时露出原侧栏。

侧栏不可用时，正文右侧空隙至少有 300 px 才自动展开，宽度上限为 350 px；空间不足则显示反色目录图标，手动展开后仍为浮层。小屏宽度限制为视口减去两侧各 16 px。

`theme` 支持 `auto`、`light`、`dark`。`auto` 优先根据页面 `body` 或根节点背景亮度选择目录配色，无法判断时回退到系统明暗偏好；页面 class/style 变化会触发更新。弹窗自身的自动配色回退为系统偏好。

目录外观遵循 X 的浅色、黑色和暗蓝色页面配色，使用细边框与蓝色选中态，不使用阴影和额外品牌行。目录字号为 13 px，条目上下内边距为 6 px；不显示文章目录标题、文章标题或底部说明，不添加行号、数量徽标或刷新按钮。收起时显示 36 px 的圆形图标。展开面板和收起图标共享一个拖动控制器，位移至少 5 px 才认定为拖动，并在捕获阶段拦截其结束后的指针点击，防止误展开。顶部短横条和图标均可拖动，聚焦后 Alt + 方向键支持键盘移动；位置保存在当前面板实例内，正文更新时保留，切换文章后重置，不持久化。

## 数据与权限边界

仅 `settings` 偏好持久化于 `chrome.storage.local`：`enabled`、`detectBold`、`detectNumbered` 默认 `true`，`theme` 默认 `auto`。标题、正文、当前章节与 DOM 引用仅存在于页面内存中，不作为阅读历史保存或上传。

清单仅申请 `storage`，内容脚本与模块资源匹配范围限于 HTTPS X/Twitter 域名及其 `www` 变体。扩展页面 CSP 限制脚本来源为自身。更多说明见 [PRIVACY.md](../PRIVACY.md)。

## 开发验证与分发

Node.js 22+ 用于开发工具。`npm ci` 安装锁定的开发依赖；`npm run lint` 执行静态检查，`npm test` 执行 DOM 与逻辑测试。先运行 `npx playwright install chromium`，再通过 `npm run test:browser` 在隔离 Chromium 中加载真实扩展，并将 X 网络请求拦截为本地 fixture。

该测试覆盖受控样例上的加载和交互，不是对线上 X 的兼容认证。真实站点的 DOM 变化仍需实际页面样例验证；测试状态必须依据真实执行结果记录。

`npm run demo` 在 `http://localhost:4173` 提供本地演示。`npm run zip` 以固定白名单收集扩展运行文件，生成 `dist/x-reader-0.1.4.zip`，不依赖文件是否已提交到 Git。测试、开发依赖和演示资源不进入安装包；用户也可直接加载项目根目录。
